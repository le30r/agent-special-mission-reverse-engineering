# Level21: отсутствующая лестница

## Симптом и причина

При входе в Level21 лестница не отображалась, хотя SCC содержал обработчик её подбора. Причина была в общем сопоставлении имён объекта: SCC сохранял каноническое имя `Lest`, а запись в MULT называлась `LEST`; браузерный `Map.get()` сравнивал их с учётом регистра. Поэтому первая запись изображения не привязывалась к SCC-объекту, и движок не создавал спрайт. Это же исключало объект из пиксельного hit-testing.

Это не проблема отсутствующего `Show Lest`: для базового `Object` начальная картинка появляется при первом назначении изображения MULT, а по умолчанию объект не скрыт. Не было найдено ни прежнего подбора, ни предмета 29 в исходном начальном состоянии.

## Проверка оригинального SCC и ресурсов

`Level21.scc` оставлен без изменений. В нём объявлены `Object Lest_ten 0 505` и `Object Lest 6 500`. Init запускает `Startlevel`/`Startlevel1` и явно показывает ряд других объектов, но не лестницу. Обработчик `Click 0 Lest Grandmother` при состоянии 0 подходит к бабушке и запускает `Bab_no`; при состоянии 1 выполняет подход, `StartW K_lest`, `Hide Lest`, затем `Addtol 29`.

В оригинальных `XSH\\SCN_21\\start.mult` (кадр 1) и `start1.mult` проверены записи и их изображения. Начальный MULT layout `Startlevel` связывает `Lest` с записью `LEST` (слот 1, child 8; растр 85×378) и `Lest_ten` с `Lest_ten` (слот 1, child 7; 51×236). `Startlevel1` не назначает им дополнительных изображений. Это два отдельных MULT-объекта, лестница и её тень; оба не являются частью `BACKGRD\\scn_21.tif`. Графика назначается сценовым объектам по кадрам MULT, а не добавляется статическим PNG. В `K_lest` на кадре 12 обновляются и ladder, и тень; следовательно, это отдельные объекты, обновляемые MULT-анимацией.

Позиции берутся из координат MULT: лестница `x≈219.91, y≈268.95`, тень `x≈186.10, y≈194.43` в координатах SceneView; фон загружен как `/generated/backgrd/Scn_21.png`. Глубины SCC сохранены: лестница 500, тень 505. Согласно [OBJECT_DEPTH](../rendering/OBJECT_DEPTH.md), первый параметр `Object` — cursor ID, второй — глубина: `6` у лестницы — курсор, не состояние и не координата.

## Восстановленная семантика имени

В оригинальном `Agent.exe` `findObject` (`0x40a8dc`) линейно перебирает список и сравнивает имя через `0x435404`, который использует таблицу uppercase (`0x43c8a4`). Значит, поиск SCC-объектов регистронезависим и возвращает первое совпадение в списке; при этом имя события Click сравнивается отдельно и побайтно. Это объясняет, почему исходная игра связывает `Lest` с MULT-записью `LEST` без команды `Show`.

## Аудит всех 47 сцен

До фикса обнаружено **5 записей MULT**, которые не связывались только из-за регистра, для **4 уникальных SCC-объектов в 3 сценах**:

| Сцена | Имя в MULT | Каноническое SCC-имя | MULT-ресурс / кадр |
|---|---|---|---|
| Level16 | `DV_17` | `Dv_17` | `Startlevel`, 1 |
| Level17 | `v1` | `V1` | `Startlevel`, 1 |
| Level21 | `STENA_20` | `Stena_20` | `Startlevel`, 1 |
| Level21 | `LEST` | `Lest` | `Startlevel`, 1 |
| Level21 | `LEST` | `Lest` | `K_lest`, 12 |

Итого до исправления: **5 пропущенных MULT-связей / 4 уникальных объекта / 3 сцены (16, 17, 21)**. После исправления: **5 из 5 разрешаются по SCC identity; остаток — 0**. В 47 сценах не найдено SCC-объявлений с именами, различающимися только регистром, и не найдено групп MULT-имён, различающихся только регистром. Единственная одноимённая декларация разных видов — Level8 `Object Barm_click` и `Active Barm_click`; регистром они не отличаются и в число ошибок не входят.

## Исправление и жизненный цикл

Добавлен общий регистронезависимый поиск `findNamedObject`, сохраняющий имя объявления SCC как runtime identity. Поиск применяется при привязке MULT, восстановлении кадров и состоянии сцен, видимости, глубине, курсоре и animation object-filter. В `SceneView.objects` ключ теперь SCC-канонический; resource spelling больше не создаёт отдельную runtime identity. Скрытое изображение сохраняется и блокирует восстановление спрайта при повторном входе.

Исправленная цепочка: загрузка объявления `Lest` → `Init Interface` и первый кадр `Startlevel` → запись `LEST` разрешается в канонический объект `Lest` → спрайт из MULT ставится в render tree по координатам/глубине → тот же пиксельный ресурс участвует в hit-test → реальный клик вызывает `Click 0 Lest Grandmother`. Ветка с бабушкой 0 не подбирает предмет; с бабушкой 1 выполняет `Hide Lest` и `Addtol 29`. Повторный клик не добавляет дубликат; возврат Level21 сохраняет скрытое состояние.

- `tests/level21-ladder.test.ts`: регистр имён, полный аудит 47 сцен, MULT-растр/позиция/глубина, hit-test, ветки Grandmother 0/1, `Hide`, предмет 29, повторный вход.
- `scripts/e2e-browser-level21-ladder.mjs`: Chromium с реальным интерфейсом, вход Level20 → Level21 кликом по порталу, проверка объектов и hit-test, подготовка только `Grandmother=1` через UI-инспектор, реальный canvas-клик для подбора, повторный клик и переход Level21 → Level20 → Level21.
- Скриншоты: [лестница на сцене](evidence/level21-ladder/01-level21-ladder-visible.png) и [после подбора](evidence/level21-ladder/02-level21-ladder-picked-up.png).
- `pnpm test`: **18 файлов, 166 тестов прошли**; аудит выдал 5 case-only MULT-записей до фикса, 0 нерешённых после него.
- `pnpm build`: прошёл (`tsc -b` + Vite production build).
- `pnpm e2e:browser:all`: **9/9 сценариев прошли**; среди них Level1 interactions, transitions, Level39, scene38, WAV, restored SCC и fault. Каталог Chromium загрузил **47/47** сцен.
- `pnpm e2e:browser:lora`: прошёл.
- `pnpm e2e:browser:inventory-combination`: сценарий дошёл до Level44 и остановился на существующем ожидании E2E о видимой ссылке возврата `To_38`: наблюдались `state=1`, `visible=false`, прямоугольник `(0,365)-(100,600)`. Этот сценарий не затрагивает ни одну из четырёх case-only пар; причина ожидания в этой работе не менялась и не исследовалась.

## Ограничения

Оригинальный EXE проверен статически; запуск оригинала и динамический trace не выполнялись. Chromium E2E для успешной ветки задаёт `Grandmother=1` через debug State Inspector как явную подготовку fixture; само взаимодействие с лестницей выполняется только пользовательским кликом по canvas. Один standalone E2E комбинирования предметов остаётся красным на отдельном Level44 ожидании `To_38` (см. результаты). Ресурсы оригинала и `Level21.scc` не изменялись.
