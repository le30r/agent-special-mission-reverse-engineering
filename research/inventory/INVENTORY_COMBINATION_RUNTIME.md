## 1. Исходный пользовательский сценарий

Игрок на вечернем визите к Лоре (`Level38`). Чтобы открыть дверь Лоры, нужно:

1. иметь **нож** и **монтировку**;
2. объединить их в инвентаре;
3. применить получившийся предмет к двери.

Текущее браузерное поведение: клик по ножу **немедленно закрывает** инвентарь
и помечает нож выбранным для сцены; применить нож ко второму предмету
невозможно — маршрута item-on-item в браузере нет.

---

## 2. Точная механика оригинального инвентаря

Оригинал — это **двухфазная выборка**, а не «выбрал и вышел».

- UI-режим хранится в `ui+4`; `case 2` — открытая панель инвентаря.
- Внутри панели есть **отложенная выборка** `ui+0x11` (pending selection) и
  **зафиксированная выборка для сцены** `scene+5` (selected item).
- **Первый клик по предмету** записывает его ID в `ui+0x11` и **оставляет
  панель открытой** (`0x40cb84`, case 2, `0x40ed08` → `*(ui+0x11) = id`).
- **Второй клик по другому предмету** пытается скомбинировать:
  `0x40ec74(inv, clicked, selected)`; при положительном результате удаляет оба
  (`0x40ec50`/Remtol), добавляет результат (`0x40ec2c`/Addtol) и сбрасывает
  `ui+0x11`. При отсутствии рецепта выборка остаётся.
- **Закрытие панели** (`0x40e9f0`, mode 2 → 0) переносит `ui+0x11` в `scene+5`
  через `0x40a194` — только теперь предмет становится «выбранным для сцены».
- Повторное открытие при ненулевом `scene+5` (`0x40e9f0`, mode 0) **снимает
  выбор** (`0x40a194(scene, 0)`), т.е. клик по кнопке инвентаря при выбранном
  предмете = отмена.

Итог: **гипотеза A верна** — панель остаётся открытой после первого выбора;
второй выбор внутри панели комбинирует предметы, а закрытие панели фиксирует
выбор для сцены. Варианты B/C/D не подтверждаются кодом.

### Как игрок применяет нож к монтировке

1. Открыть инвентарь (кнопка; `mode 0 → 2`).
2. Кликнуть нож → `ui+0x11 = 5`, панель открыта.
3. Кликнуть монтировку → `0x40ec74(inv, 2, 5)` → рецепт `2*1000+5 = 2005`
   → результат `39`. `Remtol 2`, `Remtol 5`, `Addtol 39`, `ui+0x11 = 0`.
4. Закрыть инвентарь при необходимости; кликнуть дверь при выбранном `39`.

## 3. Формат хранения и выбора предметов

Инвентарь — глобальная структура `DAT_00468518` (выделяется `0x4b8` байт):

- `+0x004 … +0x190`: 100 слотов `int`, пустой слот `-1` (`0xffffffff`).
- `+0x194`: число записей таблицы комбинаций.
- `+0x198 …`: записи `{int key; int value}` (8 байт каждая).

`Addtol` (opcode 0x0f → `0x40ec2c`) пишет ID в первый пустой слот, без проверки
дубликатов. `Remtol` (opcode 0x11 → `0x40ec50`) обнуляет **все** слоты с данным
ID. Визуально `0x40ed88` рисует непустые слоты из `XSH\Interface\large.mult`,
используя ID как номер кадра; `0x40ed08` — hit-test по сетке 4×5
(`x 487..727`, `y 18..518`, ячейка 60×100).

Выбранный предмет существует в двух регистрах:

- `ui+0x11` — временная выборка внутри панели (сбрасывается при открытии/успехе).
- `scene+5` — выборка для следующего клика по сцене (записывает `0x40a194`,
  сбрасывается после успешного `Click` обработчиком `0x40a31c`, или вручную).

Одновременно двух «выбранных для сцены» предметов нет: `scene+5` — один int.
`scene+5` живёт в структуре сцены и **не является** содержимым инвентаря;
`ui+0x11` живёт в UI-структуре.

## 4. Маршрутизация item-on-item

Цепочка в оригинале (для клика в открытой панели):

```text
WM_LBUTTONDOWN (0x40f204)
  → UI-mode dispatch 0x40cb84  (mode = ui+4)
      case 2 (inventory):
        → 0x40ed08  slot hit-test → clicked item id
        → если ui+0x11 < 1:  ui+0x11 = id          (select)
        → иначе: 0x40ec74(inv, id, ui+0x11)        (combine lookup)
            → если > 0: Remtol id; Remtol ui+0x11; Addtol result; ui+0x11 = 0
```

Это **нативный** путь; SCC `Click`/`Case` в комбинации не участвует. `Click`
обрабатывает только `scene+5` (item → объект сцены), а не item → item.

## 5. Подтверждённые комбинации (рецепт-таблица EXE)

Таблица зашита в конструктор инвентаря `0x40eacc` (не читается из файла) и
кодируется как `key = первый*1000 + второй`. Каждая пара зарегистрирована в
обе стороны → **порядок кликов не важен**.

| Первый | Второй | Результат | Имя/назначение (если установлено) |
|---|---|---|---|
| 5 | 2 | 39 | **нож + монтировка** → инструмент для двери Лоры |
| 2 | 5 | 39 | (обратный порядок) |
| 9 | 10 | 40 | item 9 + item 10 (Level3) → item 40 |
| 10 | 9 | 40 | (обратный порядок) |
| 34 | 33 | 49 | item 34 (Level32) + item 33 (Level24) → item 49 |
| 33 | 34 | 49 | (обратный порядок) |
| 49 | 31 | 50 | item 49 + item 31 (Level12) → item 50 |
| 31 | 49 | 50 | (обратный порядок) |
| 49 | 32 | 51 | item 49 + item 32 (Level17) → item 51 |
| 32 | 49 | 51 | (обратный порядок) |
| 45 | 42 | 46 | item 45 (Level22) + item 42 (Level22) → item 46 |
| 42 | 45 | 46 | (обратный порядок) |

Наблюдение: item 49 — промежуточный (результат 33+34), далее комбинируется с 31
или 32. Результаты 39, 40, 46, 50, 51 используются сценой через `Click <id>`
(в корпусе есть `Click 39/40/46/50/51 …`). Имена предметов 9/10/31/32/33/34/42/45
не восстанавливались — это вне объёма задачи (зафиксированы только их ID и
сцены выдачи). Комбинация `нож+монтировка` = **5 + 2 → 39** подтверждена
рецептом и SCC (`Addtol 5` из `Nozhik`, `Addtol 2` из `Car_click`, `Click 39
Door`).

## 6. Оригинальный EXE против браузерной реализации

|---|---|---|

| `scene+5` | `SceneView.selectedItem` (per-visit) | ✅ совпадает |
| `ui+0x11` pending | отдельный регистр | ❌ отсутствует |
| Первый клик по предмету | выбор, панель открыта | `InventoryView.pointerDown` → `selected=id; setOpen(false)` — **закрывает** |
| Второй клик по предмету | `0x40ec74` combine | ❌ отсутствует |
| Рецепт-таблица | зашита в `0x40eacc` (12 записей) | ❌ отсутствует |

`InventoryView.pointerDown` (src/scene/inventory-view.ts:91-109) — точное место,
где выбор ножа закрывает окно:

```ts
const id = itemAtInventoryPosition(this.items, x, y);
if (id > 0) {
  this.selected = id;
  this.setOpen(false);   // ← панель закрывается сразу
  return true;
}
```

## 7. Причина текущего блокера

**CONFIRMED.** Комбинация предметов в оригинале — нативный механизм EXE
(`0x40cb84` mode 2 + `0x40ec74` + зашитая таблица `0x40eacc`), а не SCC.
Браузерный порт воспроизвёл только связку «инвентарь → `scene+5` → `Click` по
объекту», но:

1. `InventoryView` закрывает панель при первом выборе (нет двухфазной выборки),
2. нет регистра pending-selection и нет рецепт-таблицы,
3. нет вызова комбинации при клике по второму предмету.

Поэтому маршрут item-on-item в браузере физически отсутствует: после клика по
ножу панель уже закрыта, и `consumeSelection`/`selectItem` отдают нож только для
сцены. Это не конфликт с Fault/Block/Fclick/Addtol/Remtol — те механизмы
ортогональны; проблема в отсутствующем режиме самой панели инвентаря.

## 8. Минимальная техническая спецификация исправления

Не добавлять «систему рецептов» — оригинал тоже не использует SCC для
комбинации; он использует **зашитую таблицу** и нативный lookup. Порт должен
воспроизвести то же самое.

### 8.1 Рецепт-таблица (константа движка)

Перенести таблицу из `0x40eacc` как `Map<number, number>`, ключ `a*1000+b`:

```ts
// key = a*1000+b -> result (both orders), faithful port of FUN_0040eacc
const COMBINE: ReadonlyMap<number, number> = new Map([
  [5*1000+2, 39], [2*1000+5, 39],
  [9*1000+10, 40], [10*1000+9, 40],
  [34*1000+33, 49], [33*1000+34, 49],
  [49*1000+31, 50], [31*1000+49, 50],
  [49*1000+32, 51], [32*1000+49, 51],
  [45*1000+42, 46], [42*1000+45, 46],
]);
```

Это константа движка, а не данные уровней; без хардкода `if (a===5 && b===2)`.

### 8.2 Двухфазная выборка в `InventoryView`

- Заменить `selected: number` на `pendingSelection: number` (аналог `ui+0x11`).
- `pointerDown` при попадании в предмет:
  - если `pendingSelection` пуст → `pendingSelection = id`, **панель остаётся
    открытой**;
  - иначе → `result = COMBINE.get(id*1000 + pendingSelection)`; при `result > 0`
    мутировать инвентарь (`removeInventory(id)`, `removeInventory(pendingSelection)`,
    `addInventory(result)`), сбросить `pendingSelection`, панель остаётся открытой.
- `consumeSelection` больше не нужен в прежнем виде: выборка для сцены
  фиксируется **при закрытии** панели (см. 8.3).
- Клик по тому же предмету при выбранном `pendingSelection` даёт
  `id*1000 + id` — не в таблице → no-op (соответствует оригиналу).

### 8.3 Коммит выборки при закрытии панели

При переходе панели `open → closed` с ненулевым `pendingSelection` вызывать
`view.selectItem(pendingSelection)` (запись в `scene+5`), затем обнулять
`pendingSelection`. Точка вызова — в `main.ts`, где сейчас вызывается
`consumeSelection`, либо колбэк закрытия `InventoryView`.

### 8.4 Отмена выбора

Клик по кнопке инвентаря при закрытой панели и ненулевом `scene+5` должен
сбрасывать `scene+5` (аналог `0x40e9f0` mode 0 → `0x40a194(scene,0)`), а не
открывать панель. Это единственное изменение семантики таба.

### 8.5 Что менять не нужно

- `SccRuntime` dispatch/Addtol/Remtol — уже верны.
- `SceneView.selectedItem`/`selectItem`/`pointerDown` — уже верны (потребление
  `scene+5` после обработанного `Click`).
- `SceneLoader.inventory` — уже глобальный и переживает переходы сцен.

Итог: изменяются только `InventoryView` (состояние + combine) и место коммита
выборки; добавляется одна константа-таблица. Production SCC/сцен не трогаем.

## 9. План регрессионных тестов

### 9.1 Основной сценарий (E2E, реальный UI)

См. `scripts/e2e-browser-inventory-combination.mjs` (сейчас воспроизводит
блокер; после исправления проходит). Проверяет:

1. Открыть инвентарь (таб).
2. Выбрать нож (item 5) → панель **остаётся открытой**.
3. Кликнуть монтировку (item 2) → срабатывает рецепт.
4. Инвентарь меняется: `[2,5]` → `[39]`.
5. Результат (39) можно выбрать/применить к двери (`Click 39 Door`).
6. SCC-ветка `Level38.scc:525` выполняется (`Remtol 39`, `Level 3 -1`).

### 9.2 Дополнительные проверки

- Выбор предмета без комбинирования → закрытие панели фиксирует `scene+5`.
- Отмена выбора (таб при `scene+5≠0`).
- Повторное открытие панели.
- Неудачная комбинация (пара без рецепта) → no-op, выборка сохраняется.
- Предмет на самом себе → no-op.
- Обратный порядок (2→5) → тоже даёт 39 (таблица коммутативна).
- Применение предмета к объекту сцены → `Click <id>` + потребление `scene+5`.
- Сохранение предметов после перехода между сценами (инвентарь глобален).
- Отсутствие дубликатов (Remtol чистит все совпадения, Addtol один слот).
- Регрессии Level1 и разговора с Лорой (`e2e:browser:lora`).

### 9.3 Юнит-тесты

- `parseScc`/Addtol/Remtol не регрессируют.
- Новая функция `combineItems(inventory, a, b, table)`:
  - `[2,5]` → `[39]`;
  - неизвестная пара → инвентарь не меняется, результат `0`;
  - обе ориентации каждой пары дают результат.
