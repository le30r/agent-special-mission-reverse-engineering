# Статус браузерного прототипа

Обновлено: 2026-10-19.

## Постоянное состояние мира (подготовка Save/Load)

- `SceneSession.capturePersistentState()` возвращает независимое plain-data представление: текущую сцену, записи всех 47 доступных scene ID (включая непосещённые с `initialized=false`), per-scene позиции/направления, SCC object states и Lstate placeholders, inventory в исходном порядке с дубликатами, карту и live-позу героя. Native capacity из 50 сцен не превращается в вымышленные Level9/49/50.
- Авторитетный источник: `SceneLoader.states` для сцен и объектов, `SceneLoader.inventory` для предметов, `SceneLoader.game.map` для bank/unlocks. Активная `SceneView` — источник актуальных координат/направления/режима героя и живых transform; `SceneDefinition` остаётся декларациями/дефолтами; `SccRuntime` не экспортируется, его local state cache не сериализуется.
- Объектные поля snapshot: `state`, `depth`, `cursorId`, `rect`, `kind`, видимость Active/Light и эффективная видимость базового Object, image (`mult` с file/frame/slot/child, `empty` после Hide или `unassigned`) и transform `{x,y,scaleX,scaleY,anchorX,anchorY}`. Transform/видимость обновляются при применении MULT и синхронизируются перед обычной выгрузкой сцены. Level21 E2E зафиксировал Ladder `Hide` как `image=empty, visible=false`, а тень — как назначенный `K_lest` frame 12 с `visible=false`; это не выводится из State. Snapshot лишь читает live Sprite и не вызывает dispose/stop/cancel.
- Setmap/Setzon теперь обновляют две независимые группы по семь unlock-флагов. Явный `legacy-zone-v1` экспортируется без выдумывания unlocks; обычная новая сессия использует `banked-v1` с нулевыми unlocks.
- Исправлено объединение SCC declaration со старым состоянием: cursor, rect, transform и другие постоянные поля больше не теряются при повторном входе. Исправлен stale hero position при snapshot: активная сцена берёт координаты из live view, включая валидные `(0,0)`; неактивные используют сохранённый SceneState.
- Следующий этап импорта ещё должен валидировать schema/content и все числовые поля до мутаций, транзакционно заменить loader state, восстановить сцену до Start, применить image/visibility/transform после SCC declarations, восстановить hero pose и вывести runtime на чистую границу. В snapshot намеренно отсутствуют Program/PC/waits, маршруты, animation elapsed/barriers, звук, UI selection, Pixi объекты/текстуры и blob URLs: оригинальный EXE их не сохраняет, а восстановление должно строить их заново. Native binary slots/header, слоты UI и неизвестные лимиты оригинала не копируются.
- Проверки: `pnpm test` — 19 файлов / 172 теста прошли; `pnpm build` — успешно; `pnpm e2e:browser:all` — 9/9 сценариев и 47/47 сцен; `pnpm e2e:browser:lora` и standalone Level21 ladder E2E — прошли. Level21 snapshot фиксирует `Lest.image=empty, visible=false`, `Lest_ten.image=K_lest/frame12, visible=false`, `Grandmother.state=1`, `inventory=[29]`. Level38 snapshot после разговора фиксирует `Lora.state=2`, `cursorId=7`, MULT `K_talke/frame11`, inventory `[4]`.

## SCC Fault (восстановлено)

- `Fault` разбирается как top-level visit-scoped список Voices; сохраняются порядок деклараций, повторы путей и first-match по имени. Некорректные записи диагностируются; единственная корпусная совместимость без `count` ограничена `Level17.scc:127` (`New_janitor1`, DERIVED), где переиспользуется предыдущее значение 1.
- Fallback встроен в обычный click dispatch после hit-test и попытки обычного `Click`: запускается только для видимого hit-объекта, при item 0, без busy/Block и если Click не исполнился. При Block клики по-прежнему направляются в Plane.
- Один синтетический handler с 50 Case-слотами разделяет программу `Goto → Setxy → StartW Speak → Setxy`; координаты берутся из world click. Движение, no-route, ожидание анимации и WAV-барьер проходят через обычные SCC scheduler, animation player и WAV runtime.
- Voices принадлежат спискам текущего посещения сцены. `Speak` заимствует выбранный Voice через event binding, не освобождая его; dispose сцены инвалидирует незавершённые callbacks и освобождает Voices.
- Оригинальный selector rand15 и его 25/75 распределение для двух ресурсов сохранены. Поскольку seed и полный порядок RNG оригинала неизвестны, браузер по умолчанию адаптирует `Math.random()` к rand15; тесты могут подставить детерминированное значение.
- Реальные Level1/Morda и Level29/Janitor проходят в Chromium с исходными WAV без E2E mute. Для Level1 подтверждены выбранный `otd_001.wav`, ненулевой PCM, кадры Speak, снятие барьера по фактическому `source.onended`, завершение SCC и неизменность inventory/Object State. Для Janitor проверены обе ветки выбора.
- Проверки среза Fault: Vitest single-fork — 161/161; стандартный параллельный `pnpm test` на этой машине упирается в три 5-секундных timeout audio/frame-тестов. `pnpm build` — pass; последние полные 9 Chromium E2E — pass; каталог сцен — 47/47. Полный набор запускается `pnpm e2e:browser:all`, Fault отдельно — `pnpm e2e:browser:fault`.

## Комбинирование предметов инвентаря (2026-10-19)

- `InventoryView` воспроизводит нативную двухфазную выборку: первый клик запоминает `pendingSelection` и оставляет панель открытой; второй ищет ключ `clicked * 1000 + pendingSelection`. Промах не меняет pending-выбор и предметы. При успехе `Remtol`-семантика удаляет все экземпляры обоих ID, затем один `Addtol` добавляет результат и сбрасывает pending.
- Неизменяемая таблица `COMBINE` хранит ровно 12 направленных записей конструктора `0x40eacc`; обратные пары заданы явно. `5 + 2` и `2 + 5` дают `39`. Используется существующий `SceneLoader.inventory`; SCC runtime и `SceneView` не менялись.
- Закрытие панели передаёт pending ID в `SceneView.selectedItem` (`scene+5`); повторный клик по закрытой вкладке при выбранном scene item отменяет выбор вместо открытия панели. Подсветка pending-слота — минимальная браузерная адаптация; точная нативная подсветка не установлена.
- Unit-регрессии проверяют клики/переходы состояния и все 12 рецептов (`25` тестов файла, `161` всего). Chromium-путь подтвердил получение монтировки через `Car_click`, ножа через `Nozhik`, комбинацию 5+2, исчезновение исходников, появление и выбор item 39.
- **Полное применение к двери пока блокируется оригинальным маршрутом/Active visibility.** В `Level38.scc` `Click 39 Door Lamp_t` зарегистрирован только для `Case 1`; на прямом применении после разговора с Лорой наблюдается `Lamp_t.state=0`, поэтому `K_mont` и переход Level3 не запускаются. Дальнейший E2E прошёл нативный `Click 39 Goto_3 Pank`, выставил `Pank=3`, вошёл в Level44 и получил item 7 из `Lampochka`. Однако перед возвратом в Level38 сохранённый после разреза гамака `To_38.state=1` имеет `activeVisible=false`, хотя `Level44.scc` содержит `Show To_38` в обеих ветках `Init Interface`; штатный `To_38` Active-hit-test поэтому не срабатывает. Без возврата нельзя выполнить `Click 7 Lamp_t Pank` (Case3), который единственный в доступных SCC-ресурсах выставляет `Lamp_t=1`. SCC и runtime-состояния напрямую не подменялись. Нужен отдельный разбор/фикс видимости Active `To_38` либо уточнение ожидаемого оригинального сюжетного пути.
- Проверки: `pnpm build` pass; 161 unit-тест прошёл при `vitest run --pool=forks --poolOptions.forks.singleFork --testTimeout=15000`; все 9 штатных Chromium E2E прошли, `pnpm e2e:browser:lora` прошёл, каталог подтвердил 47/47 сцен. E2E комбинации успешно доходит до item 7 в Level44 и сохраняет скриншоты, затем останавливается на доказанном `To_38` (`state=1`, `visible=false`), не имитируя `Door → K_mont → Level 3`.
- Chromium-сценарий: `scripts/e2e-browser-inventory-combination.mjs`. Сохранённые ключевые кадры в `research/inventory/evidence/browser-combination/` включают получение предметов, комбинацию, Pank/Goto_3 и Level44 с item7; E2E также печатает точный `To_38` state/visibility перед остановкой.

## Реализовано

- **Level1: пистолет и гамак восстановлены через общие механизмы.** Диагностика по оригинальному `Level1.scc`, `Step_01/03/07.MULT` и адресным Evidence:
  - `Click 0 Pistol Pistol` / `Case 0`: `Hide Nar`, `Goto 1060 590`, `StartW K_pistol`, `Setxy 1050 590`, `Addtol 4`. Пистолет — обычный `Object Pistol 6 1000` с внешним изображением `PISTOLET.tif`; предмет в инвентаре для него **не** требуется. `K_pistol` кадр 20 назначает `Pistol` пустой растр, затем предмет 4 пишется в инвентарь.
  - `Click 1 Slip Flag1` / `Case 0`: `Goto 350 470`, `Stop Slip`, `StartW Razres`, `Setxy 345 470`, `Remtol 1`, `State Lec_v 1`, три `Lstate`, два `Cursor`, `State Slip 3`, `State Flag1 1`. Нужен **предмет 1 (бутылка)**, выбранный в инвентаре, и `Flag1.state == 0`; `Slip.state == 1` включает обычный разговор `Click 0 Slip Slip`, а не разрез. Так гамак разрезается только один раз, бутылка исчезает из инвентаря, а состояние переходит в `Slip=3`.
- **Причина прежнего невоспроизведения.** Клики обрабатывал жёсткий список `interactive: ['Botl']`, поэтому `Pistol` и `Slip` не проходили hit-test; у внутренних MULT-растров (`Slip` — RLE `Step_01.MULT`) вообще не строился пиксельный массив попадания; выбранный предмет `scene+5` и инвентарный UI отсутствовали; `Stop`, `Remtol`, `Cursor` не разбирались; `Lstate` читался в неверном порядке аргументов; обработанный клик по объекту проваливался в click-to-walk; `Setxy` не выполнял исходную коррекцию недоступной точки.
- **Первая восстановленная группа SCC (Sol, 2026-10-18).** `Click ... [stateScene]` читает state из `SceneLoader` без создания удалённой сцены, но запускает Program в текущем runtime; `StatrW` принимает все пять реальных corpus-вызовов как `StartW`. `Fclick` хранится как load-time animation binding и синхронно dispatch-ится при естественном завершении одноразовой анимации после WAV-барьера (не при `Stop`/`Animc`); внутренний dispatch не отменяет Programs. `Block/Ublock` — отдельный булевый input-флаг: обычные клики идут в `Plane`, внутренние SCC/анимации продолжаются. В Level10/38 callback снимает блок и ведёт кат-сцену дальше. `Setmsk` переключает подготовленный visit-local TIFF; маршруты, коррекция, глубина и масштаб используют активную маску, смена не телепортирует и не перестраивает текущий route. Ресурсы альтернативных масок загружаются до входа в сцену, поэтому SCC-порядок остаётся синхронным. Проверены реальные Level10/12/16/38; каталог — 47/47.

- **Общие исправления вместо частных обработчиков.** Удалён whitelist: hit-test теперь перебирает все базовые `Object` в обратном painter-order (`abs(depth)` по возрастанию, `abs(depth) != 0`), с пиксельной маской из внешних PNG и внутренних MULT-растров. Добавлены `Stop` (opcode `0x15` → `0x404fb4(anim, 0)`: active=false, кадр 1), `Remtol` (opcode `0x11` → `0x40ec50`: очищаются все слоты с данным ID), `Cursor` (opcode `0x1f` → `+0x152`). Исправлен порядок `Lstate <name> <value> <scene>` (executor opcode 10 использует arg B как сцену). Выбранный предмет сбрасывается только после реально обработанного Program (`0x40a31c`), а не при любом клике.
- **Инвентарь как обычный UI.** Добавлена панель из оригинальных `block0/XSH/Interface/Frame.MULT` (340×600) и `large.MULT` (иконки предметов), сетка 4×5 с исходной геометрией `0x40ed08`/`0x40ed88`: `x=487..727`, `y=18..518`, слот 60×100. Клик по слоту выбирает предмет и закрывает панель; выбранный ID передаётся в следующий клик по сцене и очищается после обработки. Открытие/закрытие панели — браузерный affordance прототипа (см. ограничения), выбор и расход предмета повторяют исходную семантику.
- **Setxy с коррекцией.** `0x409708` проверяет/корректирует логическую точку тем же поиском `0x409874`, что и навигация. `Setxy 345 470` само по себе не walkable; без коррекции герой получал scale 0.01. Теперь точка корректируется (например, до `(338,489)`), глубина/масштаб пересчитываются.
- **Корректная пиксельная очередь.** `Per_botl` (`depth=900`) находится перед `Botl` (`depth=1000`) и перекрывает центр бутылки. Старый клик по центру работал только из-за whitelist; оригинальный all-Object hit-test попадает в `Per_botl`. Рабочая контрольная точка бутылки — открытое горлышко (мир `~707,342`).
- **Универсальный конвейер загрузки сцены.** `scripts/prepare-assets.mjs` больше не содержит `supportedScenes`: сцены обнаруживаются по фактическим `Scripts\Level*.scc` (47 файлов, `Level9.scc` отсутствует), зависимости — по рекурсивному `Inc`, `Back`/`Mask`, каждому `Anim`/`Animc`, `Setmsk` и внешним изображениям внутри MULT-записей. `public/generated/scenes.json` (version 2) содержит для каждой сцены URL SCC, включённых SCC, фона, исходной и альтернативных масок, всех MULT и внешних PNG, а также список отсутствующих обязательных/необязательных зависимостей. Полный отчёт: [`SCENE_CATALOG.md`](SCENE_CATALOG.md).
- **Ленивая загрузка и освобождение ресурсов.** В браузере манифест загружается один раз, но данные сцены (SCC, mask, MULT, фон, внешние изображения) — только при входе. `SceneSession` откладывает переход до готовности асинхронной загрузки, сохраняет старую сцену до этого момента, затем пересоздаёт `SceneView` и освобождает MULT-текстуры, внешние изображения и фон предыдущей сцены (с reference counting для общих URL). На старте в видеопамять не попадает корпус текстур.
- **Сцены без `Startlevel`.** Для Level26/42/43/45/46/48 layout отсутствует: это допустимое состояние (`layoutAnimation=null`, `layout=[]`), а не ошибка. `Stop*`/`Walk*`, `Active`/`Light`, Portal и SCC-команды продолжают работать.
- **Рекурсивный `Inc`.** Анимации из `Cursor.scc`, `Mainhero.scc`, `Ylisa.scc`, `Step*.scc`, `Grav.scc`, `Grot.scc` входят в определение сцены; `Object Interface` из `Cursor.scc` объявляется так же, как в оригинальном парсере.
- **`SceneView` — одна «посещаемая» сцена.** Отдельный Pixi-слой (фон + `world` + герой), собственный `SccRuntime` и собственный `AnimationPlayer` пересоздаются на каждый вход; `SceneLoader`/`SceneState` хранят долгоживущие данные: `State` объектов, `Objzet`-depth, последний применённый MULT-кадр, `Active`/`Light` visibility, признак пустого MULT-имени базового `Object`, позицию и направление героя, глобальный инвентарь. `SceneState`-записи пересобираются из деклараций с переносом State/depth/MULT-ссылки/visibility, поэтому подобранная бутылка и её пустой кадр переживают 1→39→1.
- **Явная граница перехода.** `Level`, `Goport` и отладочные кнопки только вызывают `SceneLoader.schedule`; применяется переход в начале тика через `SceneLoader.enterPending` (`releaseProgram → disposeRuntime → prepare → Init (только первый вход) → position → Start → scene+4=1`). Прежний SCC-runtime отменяется, Pixi-ресурсы освобождаются, состояние остаётся. Журнал переходов различает источник: `[SCC]`, `[debug]`, `[boot]`.
- **Вход в сцену.** Позиция из `Portal[i]` проходит оригинальную коррекцию маски `0x409874` (`correctPosition`, вынесена из `buildRoute`), глубина/масштаб считаются из маски и `Focus` сцены, камера — `updateScroll(0, x, mask.width, 800)`. Без портала используется позиция, записанная реальным Init `Setxy` (Level1: `1199 524`) или сохранённая при предыдущем входе; затем применяется поза `Stop<direction>`. Отдельного предварительного разбора Init `Setxy` больше нет.
- **Отладочное переключение** `?debug=scenes`: раскрывающийся список кнопок `#debug-scene-<id>` для всех 47 обнаруженных сцен (ID берутся из манифеста) и панель с активной сценой, `loading`, `loadError`, числом загруженных наборов ресурсов, источником входа, позицией/направлением, коррекцией маски, размером сцены, `Focus`, depth/scale/scroll, `zone`, числом Init на сцену, журналом переходов, Lstate-placeholder'ами, состояниями объектов активной сцены, `Goto_5`/`Goto_11.visible`, инвентарём, `selected`, `Botl`/`Pistol`/`Slip`/`Flag1`/`Lec_v` state и фактическим sprite-состоянием (`visible/removed`, размер, depth, мир). Режим `?debug=depth` показывает тот же painter order и кадровый журнал для активной сцены (кнопки доступны и там).
- **Show/Hide разделены по типам.** `Active` и `Light` хранят байтовый флаг `visible` (`+0x297`); `Show`/`Hide` пишут его, `Active` по умолчанию скрыт. Базовый `Object` не имеет этого поля: `Show` — no-op, `Hide` очищает MULT-ссылку (`imageHidden`), а следующий кадровый MULT-event восстанавливает изображение. Отсутствующее имя молча пропускается. Идемпотентность и перенос флага при повторном входе покрыты тестами.

Browser playback/error policy — адаптация порта, не подтверждённая динамическим поведением `Agent.exe`.
- **D/E/F/G: единый контракт WAV состояний и ownership.** Scene visit владеет стабильными Voice по Event; отдельный play-generation владеет abort/controller/handle/source. Non-repeat replay заменяет прежний запуск; callbacks проверяют scene/run identity. Оригинальный format tag записан в manifest: shared PCM имеет общий playback для alias одного RSS key, private ADPCM — независимые Voice. Конвертирование в browser PCM не меняет эту семантику.
- Только explicit no-device/silent backend использует encoded duration и строгое `elapsed > duration` (включая Repeat); низкоуровневый `SilentVoiceClock.stop()` не меняет deadline. В Web Audio `pending` fetch/decode, `waiting-context` и autoplay restriction не являются EOF. Handle terminal-settles один раз с `ended/stopped/replaced/failed/disposed`; callback лишь обновляет состояние, SCC продолжается после animation inactive и следующего poll. Для `Razres` требуется реальный EOF `KONST/005.WAV`.
- Browser error-policy: отсутствующий/повреждённый WAV и ошибка запуска дают terminal `failed`, scheduler снимает диапазон обычным путём. Подготовка fetch/decode имеет отдельный 30-секундный error deadline (настраивается в backend), с abort и защитой от позднего source. Это не таймер успешного окончания звука и не watchdog `StartW`. Autoplay/suspension ожидают жеста и resume, без повторного старта уже scheduled source и без скрытого silent fallback.
- Fram hooks опрашиваются внутри **каждого** catch-up перехода player, включая natural-end проверку; проход читает изменяемый cursor в source order. A возвращает cursor в свой диапазон, соседний B не стартует; после ready A → B передаётся в том же проходе. Эффекты проверяют Voice ready, а не frame-edge latch. Inline `Fram ... WAV Repeat` распознаётся во всех восьми реальных декларациях; Stop/Start без промежуточного кадра заново запускает loop.
- Диагностика отделяет stable `voiceId`, `playGeneration` и backend `playbackId`, сохраняет context state; `source.onended` обозначает естественный callback, а не общий cleanup после Stop. `voice.scheduled` при suspended context не объявляется playing. Коллекции содержат ограниченное число Voice, а не историю всех запусков.
- Исправления A/B/C сохранены: walk-click не уничтожает scene audio; unload останавливает sources и отменяет loads; Level1 interaction E2E использует disposable target, E2E-mute не устанавливается в ручную вкладку. Обычный GainNode(0) не меняет правила завершения.
- Scene-owned playback/decode отменяется при выгрузке, а локальный Stop-signal Voice связан с запросом Fetch/Decode; generation guard не даёт позднему событию старой сцены менять новый animation barrier или запускать звук. `Stop <anim>` останавливает первый latched event этой анимации, не все звуки сцены и не глобальную музыку.

## Отличия от оригинального движка

- **Приближение:** BGRA исходные данные сохраняются, но перед Pixi используется изолированный straight-alpha перенос каналов; точное смешивание DirectDraw, цветовое воздействие, округление и color-key нюансы не эмулируются полностью.
- **Приближение:** внешние TIFF преобразуются `sips` в PNG при `pnpm prepare:assets`; геометрия/цветовая конверсия TIFF не гарантирует идентичность оригинальному загрузчику. Маски читаются из оригинальных TIFF (UTIF), фоны — из подготовленных PNG.
- **Приближение:** переходы кадров и перемещения считают `deltaMS` браузерного тикера. Таймеры MULT используют исходный целочисленный `floor(1000/rate)`; wall-clock и драйверные задержки DirectSound в браузере не моделируются.
- Модель scheduler анимаций сохраняет независимость обычных SCC-анимаций (`Start` не отменяет остальные jobs); исключение — направленный Walk, который согласно evidence навигации управляется отдельным единственным current-Walk слотом. Реальное одновременное воздействие иных SCC-анимаций на один объект остаётся в рамках доступного подмножества.
- **Приближение:** при повторном входе запись объекта пересобирается из декларации, а State/depth/MULT-ссылка/`Active`/`Light` visibility и `imageHidden` переносятся; идентичность самой записи не сохраняется. Последний применённый MULT-кадр накладывается заново, что воспроизводит наблюдённое сохранение пустого кадра Botl, но не доказывает попиксельную идентичность оригиналу.
- **Исправление прототипа (не отличие от оригинала):** до рефакторинга `stop0…stop7` делили одну текстуру из-за ключа кэша без идентичности файла; теперь направление позы отображается корректно.
- **Исправление прототипа:** соседние `Case` теперь разделяют один Program, а внешние MULT-записи `-14` применяются как изображения и предзагружаются для всех анимаций, а не только для `Startlevel`.
- Сценовые клики используют пиксельный цветовой ключ для **всех** базовых `Object` (внешние PNG + внутренние MULT) и прямоугольный Active-hit-test для `Active`. Полный оригинальный UI hit-test, курсорные изображения и часть SCC-событий не реализованы; инвентарный UI — частичная реконструкция (см. ограничения).
- Загружаются все 47 обнаруженных сцен; загрузка, вход, Portal/Init/Start и переходы проверены в браузере для всего каталога. Глубина интерактивных сценариев подтверждена для Level1/38/39/40/47; остальные сцены проверены на загрузку и вход, но не на полное прохождение. Это не эмуляция всего движка.
- Компаратор возвращает 0 для одинакового `abs(depth)`, но точный tie order внутреннего `FUN_0044061c` не установлен. Прототип детерминированно сохраняет порядок вставки; это документированное отличие/приближение, без искусственного правила по имени или Y.

## Известные ограничения

- **Инвентарный UI — частичная реконструкция.** Панель, иконки, двухфазный выбор, рецепты и перенос `pendingSelection → SceneView.selectedItem` реализованы; открытие/закрытие панели остаётся отдельной кнопкой-таб браузерного прототипа, а не полной реконструкцией UI-mode машины (`uiState=0/2`, `scene+0x740`). Курсорные ID из `Cursor` сохраняются, но изображение курсора не рисуется. Для door route также не восстановлена работоспособность активного выхода Level44: SCC задаёт `Show To_38`, но браузерный статус остаётся `visible=false` при `state=1`; из-за этого не достигается `Lamp_t=1` перед `Click 39 Door`.
- **Равные depth в hit/painter-порядке:** оригинальный нестабильный сорт восстановлен статически, но браузер пока использует стабильный runtime-порядок как явное приближение; отдельная реализация native-сортировки остаётся будущей работой.
- **`Remtol` над packed-массивом.** Оригинал очищает все из 100 фиксированных слотов; порт удаляет все совпадения из packed-массива. Наблюдаемая упаковка `0x40ed08` и порядок иконок совпадают.
- **Реализован не весь SCC-subset.** `Shift`, `Setmap`, `Egame`, Cursor-изображения и часть UI-событий остаются вне реализации; `Setbcr` и `remStartW` в этом EXE подтверждённо игнорируются. В браузере нет map UI, поэтому отдельный gate открытия карты пока отсутствует. Проверенный объём этой группы: реальные Level10/12/16/38 сценарии, общие переходы 1→38→1 и 39→40→39→47, а также Fault-сценарии Level1/29.
- **`Setbck` реализован.** Пути `Back`/`Setbck` обнаруживаются из SCC и includes, конвертируются в PNG и предзагружаются в рамках одного посещения сцены. Команда синхронно меняет текстуру фона, не затрагивая навигационную маску или объекты. При повторном входе фон снова выбирается сценарием `Start`; ресурсы освобождаются с учётом общих ссылок и ошибок загрузки. Регрессии: `tests/setbck.test.ts`, `tests/level23-dialogue.test.ts`, `tests/scene-manifest.test.ts`. Новые декоративные фоны не меняют `contentId` существующих сохранений.
- **Музыка остаётся отдельным незавершённым трактом.** `Smusic` пока no-op; WAV и video audio продолжают совместно звучать в browser mixing policy. Native policy mix/duck/stop не подтверждена.
- **SclipW real playback и barrier реализованы** в P1 (2026-10-22); подробности, commit SHA и проверенные ограничения приведены в конце этого документа.
- Сцена, отсутствующая в манифесте, регистрируется как `unsupported` в отладочной панели, текущая сцена сохраняется. Манифест полностью генерируется из оригинальных `Level*.scc`; добавление сцены = добавить оригинальный SCC/ресурсы и пересобрать ассеты, ручной список не нужен.
- `Active` — невидимая интерактивная область; её depth не участвует в painter order, как и в оригинале (`Active`-рендер — no-op). Hit-test и `visible` реализованы.
- Возврат в Level1 через `Portal[1]` даёт скорректированную точку `(1396,269)` и `depth=255`, поэтому масштаб героя `0.32`. Это следствие подтверждённой коррекции `0x409874` для недоступной точки портала, а не дефект прототипа.
- `SceneView` требует DOM/WebGL; node-тесты покрывают слой определений/загрузчика/входа/visibility, а рендеринг и реальные координатные клики проверяются headless Chromium через `pnpm e2e:browser`. CDP `source.start()` подтверждает передачу AudioBuffer в Web Audio, но не гарантирует физический/акустический вывод, подключение устройства или слышимость на выходе; автоматического CI-браузера в репозитории нет.
- `Takedr1`, `K_pistol`, `K_nar` и `Razres` подключены к WAV runtime; при отсутствии `AudioContext` работает логический silent clock с точным `elapsed > duration`. Autoplay и codec/load error recovery — явные браузерные политики; playback identity следует исследованному разделению shared PCM/private ADPCM (§5/§12), без динамической сверки с Agent.exe. `Smusic` — no-op.
- Pixel-accurate compositor и полный оригинальный sound system не подтверждены запуском Agent.exe. SCC Block/Plane и Fclick/WAV synchronization интегрированы в восстановленные модели, но это не эмуляция всего native UI.
- Painter order сортирует героя вместе с объектами. Источник hero depth подтверждён маской+Focus, глубины сценовых объектов — SCC declaration/`Objzet`/кадровыми событиями. При равных `abs(depth)` сохраняется стабильный порядок вставки; оригинальный tie order неизвестен. Это не DirectDraw byte-for-byte и не per-pixel occlusion.
- Init и Start — разные Program и могут сосуществовать; на свежем Level1 Start не активируется, потому что SclipW-yield оставляет `State Stat_v/Slip` равными 0. Это проверено интеграционно и в E2E, но не является полной эмуляцией всех возможных Init-графов.
- `sips` нужен для подготовки PNG игровых TIFF; он присутствует в текущем macOS окружении.

## Открытые вопросы (не блокируют пистолет и гамак)

1. **Inventory UI-mode machine.** Точные переходы `uiState=0/2`, роль `scene+0x740`, `0x40e9f0`/`0x40ea88` и оригинальные кнопки открытия панели; двухфазная выборка, комбинации и отмена по вкладке подтверждены. Открытие остаётся браузерным affordance.
2. **Cursor rendering.** `Cursor name value` пишет `+0x152`; как ID отображается в курсоре (какой ресурс/атлас/состояние) — не восстановлено.
3. **Единый sorted hit-test.** Оригинал держит `Object`, `Active`, `Light` и `Mainhero` в одном painter-массиве. Вопрос: как именно `vtable+8` для `Light`/`Mainhero` и tie-order влияют на клик при перекрытии? Порт проверяет `Active` отдельной фазой и не включает `Mainhero` в пиксельный тест.
4. **`Setxy`/`0x409708`.** Коррекция точки и FPU-преобразование масштаба восстановлены приближённо через `correctPosition`/`scaleAt`; точная численная последовательность `0x409874`/`0x409708` не проверена динамически.

## Save/Load Core — feature/save-load-core

**Срез:** 2026-10-19. Реализован программный Save/Load Core поверх Persistent State Foundation; UI, слоты и браузерное хранилище по-прежнему вне scope.

- `SaveCodec` сериализует `GameSaveV1` в canonical JSON и envelope с SHA-256 UTF-8 digest. DTO использует `PersistentWorldSnapshot`, сохраняет порядок/дубликаты inventory, scene/object order, placeholder/Lstate, image `empty/unassigned/mult`, cursor/depth/transform/visibility, карту и hero mode. Digest — целостность, не аутентификация.
- Валидатор проверяет формат/версию/contentId, размер payload 2 MiB, active Level, уникальные сцены и SCC identities, State/item/map bounds, finite transforms/coordinates, placeholder rules и точную MULT-цепочку. `SceneAssetProvider` contentId считается от нормализованных путей и байтов SCC/MULT/mask/background/shared assets; семантическое изменение контента несовместимо.
- `SceneSession.canSave()` — read-only gate после post-tick: запрещает отсутствие активной сцены, pending/pendingLoad/transition, активный SCC Program, movement, конечную one-shot анимацию, media barrier, временный Block mode, restore и открытый/pending inventory selection. Ambient loops не блокируют Save.
- Import сначала валидирует вход, создаёт новый `SceneLoader` и isolated provider, грузит/проверяет сохранённые MULT references всех посещённых сцен, собирает detached active `SceneView` и восстанавливает world до dispatch. Только затем атомарно подменяет loader/view/provider, инвалидирует pending load, dispose-ит старую сцену и освобождает старые ресурсы. Ошибка подготовки оставляет старую сессию нетронутой.
- Restore не сериализует Program/PC, animation clocks, Fclick/audio handles или route. Посещённый active Level не получает Init повторно; Mainhero навигационной сцены получает Stop0 с mask correction/depth/scale/camera, затем обычный Start ровно один раз. Сохранённые object visuals назначаются без Fram/Sound/Fclick callbacks; эффекты нового Start остаются авторитетными. Same-scene Load принудительно строит отдельный candidate visit.
- Resource ownership защищён forked `SceneAssetProvider`: candidate загружает независимые scene definitions/MULT textures, background/external textures используют ref counts; old provider освобождается только после swap. Старые асинхронные callbacks захватывают provider своего поколения, а restore блокирует flush/input до commit.

## Save/Load UI — feature/save-load-ui

**Пользовательская инструкция:** F2 открывает сохранение, F3 — загрузку; альтернативно нажмите кнопку «Сохранить / загрузить» в верхней части экрана. Выберите один из шести слотов. Для нового слота задайте название; занятый слот перезаписывается только после отдельного подтверждения. Escape закрывает меню. Если SCC-программа, движение, анимационный барьер или переход ещё активны, меню всё равно открывается, но сохранение недоступно с объяснением; после завершения действия eligibility проверяется повторно.

- `SaveRepository` хранит по одному envelope `SaveCodec` в каждом независимом ключе `agent-revers.save.v1.slot.0` … `.5`. В индекс или runtime-state данные не дублируются. Запись — один `localStorage.setItem`; ошибка quota/security/write не удаляет и не переписывает предыдущий слот. Digest проверяется при чтении; повреждённые и несовместимые слоты остаются на месте, отображаются отдельно. `storage` event обновляет список между вкладками.
- Перед записью сравнивается исходное содержимое слота, увиденное при выборе. При расхождении выводится конфликт, без автоматической перезаписи. `localStorage` не предоставляет CAS, поэтому остаётся микроскопическое окно гонки между сравнением и setItem; одновременно открытые вкладки поддерживаются с этой оговоркой.
- Экспорт слота или текущего eligibility-safe snapshot скачивает тот же JSON-envelope `storageVersion: 1`, `payload` (canonical `GameSaveV1`) и SHA-256 UTF-8 `integrity`. Внутри только сериализуемое игровое состояние и ссылки на игровые ресурсы; текстуры/медиа/логи не включаются. Текущий экспорт не меняет мир и не запускает SCC.
- Импорт принимает `.json` до 2 MiB payload (envelope — до лимита codec), проверяет структуру/digest/contentId и показывает metadata перед явной загрузкой. Используется тот же `SaveCodec` и `SceneSession.importSave()`; слоты не изменяются. Ошибка оставляет живую сессию и слоты нетронутыми. Переносимый файл загрузится только в движке с совместимым `contentId` и поддерживаемыми сценами/ресурсами.
- После перезагрузки браузера игра **не** загружается автоматически: нажмите F3 и выберите слот. Слоты зависят от origin/browser profile, очистка данных сайта или недоступный/переполненный `localStorage` могут сделать их недоступными; JSON-файл служит переносимым резервом. Сырые технические причины остаются в console, игроку показывается короткое сообщение.

**Проверки UI-среза:** `pnpm test` — 21 файл / 182 теста; `pnpm build`; Chromium UI roundtrip `pnpm e2e:browser:save-load-ui` — реальный canvas pickup → F2/write → hard reload → F3/restore, UI JSON export action → очищенные слоты → file picker/preview/confirmed import без создания слотов; Save/Load Core E2E; Level21 ladder → F2/save → hard reload → F3/load с item 29, скрытыми лестницей/тенью, Grandmother state и без повторного Init; `pnpm e2e:browser:all` — 9/9, включая каталог 47/47; `pnpm e2e:browser:lora` — passed. `Level44 To_38` не изменялся.

**Ограничения:** localStorage не даёт атомарного compare-and-swap: версия проверяется непосредственно перед единичным `setItem`, но между проверкой и записью остаётся узкое окно гонки. Устройства/профили, очистившие данные origin, сохраняют переносимость через JSON export; старые JSON могут быть отклонены при изменении `contentId` или schema. Проверка `localStorage` ограничена текущим browser origin/profile.
