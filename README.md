# Agent: Special Mission — Browser Engine

Независимая браузерная реализация движка игры **«Агент: Особое задание» (2001)** на TypeScript и PixiJS. Репозиторий предназначен для исходного кода движка, технических исследований и документации, а не для распространения игры.

**Оригинальная игра и её ресурсы не поставляются с движком.** Для запуска нужна собственная правомерно полученная копия. Права на игру, изображения, сценарии, звук и видео принадлежат соответствующим правообладателям; наличие копии само по себе не предоставляет дополнительных прав на использование или распространение ресурсов.

## Возможности

- Интерпретатор SCC: события, состояния объектов, переходы и ожидания.
- Декодирование и воспроизведение MULT-анимаций.
- Загрузка оригинальных сцен и взаимодействий по сгенерированному каталогу.
- Перемещение героя, маски, слои и отрисовка в браузере через PixiJS.
- Инвентарь, выбор и комбинирование предметов.
- WAV-аудио и синхронизация с анимациями.
- Локальные сохранения и загрузка, игровая карта.
- Видеоролики через подготовленные MP4.

Это исследовательский порт, не подтверждённая точная копия оригинального движка. Наличие всех ресурсов не доказывает полную проходимость или совместимость. Фоновая музыка командой `Smusic` пока не воспроизводится. Некоторые исследовательские документы описывают историческое состояние реализации.

## Быстрый старт

Нужны Git, **Node.js 22.18+**, **pnpm 10.12.4**, `ffmpeg` и `ffprobe` на `PATH`. FFmpeg должен поддерживать PNG, исходные AVI-кодеки, `libx264` и AAC. Если извлекаете установочный CAB, нужен также [unshield](https://github.com/twogood/unshield). Node используется в том числе для [запуска TypeScript при подготовке ресурсов](https://nodejs.org/api/typescript.html).

Примеры установки системных инструментов (Node.js и pnpm установите отдельно):

```bash
# macOS с Homebrew
brew install ffmpeg unshield

# Debian / Ubuntu
sudo apt-get install ffmpeg unshield
```

На Windows можно выполнять последовательность в WSL с Linux-версиями инструментов. Нативный Windows-запуск отдельно не проверен.

```bash
git clone https://github.com/le30r/agent-special-mission-reverse-engineering.git
cd agent-special-mission-reverse-engineering
pnpm install --frozen-lockfile
```

Разместите файлы **своей копии игры** в структуре ниже, затем:

```bash
pnpm extract:assets
pnpm check:assets
pnpm prepare:assets
pnpm dev
```

Откройте адрес, напечатанный Vite, обычно **http://localhost:5173/**. Если порт занят, Vite выберет другой. Все команды выполняются из корня клона. `pnpm dev` и `pnpm build` также запускают подготовку через `predev` / `prebuild`; повторная подготовка использует готовые файлы, когда это возможно.

## Оригинальные игровые ресурсы

### Что требуется

Для исследованного издания достаточный исходный набор:

| Источник | Нужные файлы | Назначение |
| --- | --- | --- |
| Установочный InstallShield-архив | `data1.cab`, `data1.hdr` и дополнительные тома, если они есть в вашем издании | Содержит `block0.rss` и каталог `Scripts` |
| Дерево файлов диска | `block1.rss` … `block11.rss` | Изображения, маски, анимации, WAV и общие ресурсы |
| Каталог `Data` диска | `Title.avi`, `Titres.avi`, `Rolik1.avi`, `Rolik2.avi`, `Rolik5.avi`, `Final.avi` | Все шесть видеороликов |

Вместо CAB можно предоставить уже извлечённые `Scripts/` и `block0.rss` из собственной установки. Сохраняйте **весь каталог `Scripts`**, включая включаемые SCC, а не только `Level*.scc`; сохраняйте исходную кодировку Windows-1251 и имена файлов.

`Setup.exe`, `Agent.exe`, DLL, образы дисков и MP3 не нужны браузерному runtime. При извлечении CAB `unshield` может также извлечь EXE/DLL: они остаются в локальном игнорируемом дереве и не исполняются. Сам образ диска pipeline не распаковывает: смонтируйте свою копию средствами ОС и скопируйте перечисленные файлы. Поддержка произвольных переизданий и других установщиков не заявляется.

### Структура перед извлечением

Создайте `agent-original/` в корне клона и скопируйте файлы с диска:

```text
agent-original/
└── extracted/
    ├── data1.cab
    ├── data1.hdr
    ├── block1.rss
    ├── block2.rss
    ├── …
    ├── block11.rss
    └── Data/
        ├── Title.avi
        ├── Titres.avi
        ├── Rolik1.avi
        ├── Rolik2.avi
        ├── Rolik5.avi
        └── Final.avi
```

`pnpm extract:assets` извлекает CAB через `unshield` при отсутствии установленных `Scripts` или `block0.rss`, затем распаковывает все 12 RSS встроенным скриптом:

```text
agent-original/
├── extracted/                         # файлы из предыдущего примера
├── game-installed/
│   └── Program_Executable_Files/
│       ├── block0.rss
│       └── Scripts/
│           ├── Level1.scc
│           ├── Mainhero.scc
│           └── …                     # все оригинальные SCC
└── game-resources/
    ├── block0/                        # содержимое block0.rss
    │   ├── XSH/Interface/
    │   └── TZU/Interface/Map/Map.TIF
    ├── block1/                        # содержимое block1.rss
    │   └── Xsh/Base/
    └── …                             # block2 … block11
```

Если это дерево уже подготовлено, извлечение можно пропустить. Повторное извлечение RSS проверяет совпадение существующих файлов и отказывается заменять отличающиеся. Извлекатель не изменяет исходные RSS, SCC или AVI. На файловых системах с учётом регистра важны имена `Program_Executable_Files`, `Scripts`, `Data` и исходный регистр внутренних каталогов RSS.

По умолчанию используется только `agent-original` **этого клона**. Другой каталог задаётся явно переменной `AGENT_ORIGINAL_DIR` (абсолютной либо относительно корня клона). Пример для POSIX shell:

```bash
export AGENT_ORIGINAL_DIR="/absolute/path/to/my/agent-original"
pnpm check:assets
pnpm prepare:assets
pnpm dev
```

Переменная должна быть установлена для каждой команды, которой нужны оригиналы. `.env` автоматически этими Node-скриптами не читается. Автоматического поиска соседних checkout или домашних каталогов нет. Если выбираете нестандартный каталог внутри репозитория, добавьте весь этот каталог в свой `.git/info/exclude`; безопаснее хранить нестандартное дерево вне клона.

## Подготовка ресурсов

`pnpm check:assets` ничего не конвертирует: проверяет каталоги, наличие шести AVI, инструменты и ссылки SCC/MULT. Печатает выбранные пути, число сцен и пропуски обязательных зависимостей; при ошибке завершается ненулевым кодом. Для исследованной копии обнаружено **47 сцен и 0 пропущенных обязательных зависимостей** — это результат проверки корпуса, не гарантия совместимости других изданий.

`pnpm prepare:assets` выполняет подготовку браузерного дерева:

| Формат | Обработка | Результат |
| --- | --- | --- |
| RSS | Предварительно `pnpm extract:assets` | `agent-original/game-resources/block0` … `block11` |
| SCC | Обнаружение сцен и рекурсивных `Inc`, копирование без перекодирования | `public/resources/*.scc` |
| MULT | Копирование зависимостей сцен и общего интерфейса; декодирование в браузере | `public/resources/block*/…` |
| TIFF | Фоны, внешние изображения MULT и карта → PNG через FFmpeg (JPEG внутри TIFF предварительно собирается с таблицами и метаданными цвета, без перекодирования); маски копируются для runtime-декодера | `public/generated/backgrd/`, `tzu/`, `interface/`; оригиналы в `public/resources/` |
| WAV | Отдельные PCM signed 16-bit копии через FFmpeg, без изменения оригиналов | `public/generated/audio/block*/…` |
| AVI | Все шесть → MP4, H.264/yuv420p + AAC; проверка размеров, длительности и fps | `public/generated/video/*.mp4` и `manifest.json` |

Видео можно подготовить отдельно командой `pnpm prepare:video`. Она обрабатывает **Title, Titres, Rolik1, Rolik2, Rolik5 и Final**, а не только вступление. Неподготовленный или отсутствующий ролик считается ошибкой.

Файл `public/generated/scenes.json` содержит манифест сцен, URL ресурсов и диагностику; `public/resources/resource-index.json` — индекс имён без учёта регистра. Браузер загружает ресурсы сцен через эти манифесты. Итог команды показывает `Loadable scenes`; ошибки нельзя считать успешной подготовкой только потому, что часть файлов уже появилась.

Первый запуск конвертирует весь корпус и может занять время. Повторные запуски используют кеш; для замены копии/издания используйте новый чистый клон, чтобы старые сгенерированные файлы не смешивались с новыми.

## Запуск и сборка

```bash
pnpm dev             # подготовка + dev-сервер
pnpm build           # подготовка + TypeScript check + production build в dist/
pnpm preview         # локальный просмотр уже построенного dist/
```

Для preview откройте напечатанный адрес, обычно **http://localhost:4173/**. Не открывайте `dist/index.html` через `file://`: загрузке нужны HTTP URL. Текущая конфигурация рассчитана на корень сайта `/`, не на произвольный GitHub Pages subpath.

**`dist/` включает подготовленные игровые ресурсы.** Это локальная сборка, не свободно распространяемый дистрибутив. Не загружайте её на GitHub/хостинг без необходимых прав.

## Управление

| Действие | Управление |
| --- | --- |
| Перемещение и взаимодействие | Щелчок по сцене/объекту |
| Инвентарь | Вкладка интерфейса; выбор предмета и затем цели |
| Карта | `F1`; `F1` или `Escape` для закрытия |
| Сохранение / загрузка | `F2` / `F3` или кнопка «Сохранить / загрузить» |
| Закрытие окна сохранений | `Escape` |
| Пропуск видео | Щелчок левой кнопкой или клавиша |

Браузер может потребовать пользовательский жест для звука или кнопку запуска видео. Сохранения локальны для браузера и origin: другой порт, профиль или очистка данных сайта могут сделать их недоступными.

## Разработка и исследования

- `src/` — движок и браузерный интерфейс; `tests/` — тесты.
- `scripts/` — подготовка ресурсов и E2E tooling.
- `research/` — исследования [MULT](research/mult/MULT_FORMAT.md), [SCC](research/scc/SCC_RUNTIME.md), [аудио](research/audio/AUDIO_RUNTIME.md), [видео](research/video/README.md), [карты](research/map/README.md), [сохранений](research/save-load/SAVE_LOAD_RUNTIME.md).
- `pnpm test:tooling` — автономные тесты извлекателя на собственных синтетических данных, без игры.
- `pnpm test` — основной набор; многие тесты требуют локальных оригиналов и подготовленных ресурсов. Corpus-тест MULT дополнительно использует локальный ignored `research/mult/verification.json`, генерируемый `python3 research/mult/mult_probe.py`; это не обязательный шаг запуска игры.

## Перед публикацией

Локальные оригиналы, конвертированные ассеты, сборка и временные артефакты игнорируются Git. Для собственных PNG-иллюстраций и fixtures предусмотрены исключения `docs/images/authored/` и `tests/fixtures/authored/`; оригинальные игровые данные туда помещать нельзя.

**Обнаруженные ранее отслеживаемые скриншоты игры перечислены в [аудите публикации](docs/PUBLICATION_AUDIT.md).** `.gitignore` не удаляет уже отслеживаемые файлы и не очищает историю. Аудит не является разрешением на публикацию текущего дерева или истории; решение по этим материалам нужно принять отдельно. Никакие игровые файлы или коммиты в рамках подготовки README автоматически не удаляются.
